Objectif du projet

Notre objectif consiste à développer un programme capable de lire des instances TSP, construire une solution rapidement, puis améliorer cette solution.

Le projet a été réalisé en C++.

Lecture des fichiers TSP

Nous avons créé une structure InstanceTSP permettant de stocker :

  • Le nom de l'instance
  • Le nombre de villes
  • Les coordonnées des villes
  • La matrice des distances

Le programme lit ensuite les fichiers .tsp contenant les données du problème.

Lorsque les coordonnées des villes sont présentes, les distances sont calculées avec la distance euclidienne.

Matrice des distances

Les distances entre les villes sont stockées dans un tableau 1D dynamique.

Même si les distances représentent une matrice, elles sont enregistrées dans un seul tableau afin d'optimiser la mémoire.

La formule utilisée est :

distance[i * nb_villes + j]

Algorithme glouton

La première solution est construite avec un algorithme glouton.

Le principe est de partir d'une ville, puis de choisir à chaque étape la ville non visitée la plus proche.

Étapes de l'algorithme :

  1. Choisir une ville de départ
  2. Marquer cette ville comme visitée
  3. Chercher la ville non visitée la plus proche
  4. L'ajouter au chemin
  5. Recommencer jusqu'à visiter toutes les villes
  6. Revenir à la ville de départ

Cette méthode est très rapide, mais elle ne donne pas toujours le meilleur chemin possible.

OR-opt

Après la construction du chemin glouton, nous appliquons une amélioration appelée OR-opt.

Le but est de réduire la longueur totale du trajet.

Pour cela, l'algorithme teste différents déplacements de villes dans le chemin.

Contrairement à la première version, la version rework ne garde pas la première amélioration trouvée.

Elle teste tous les déplacements possibles, puis sélectionne le meilleur déplacement, c'est-à-dire celui qui réduit le plus la distance totale.

Recherche de la meilleure solution

Le programme ne teste pas une seule ville de départ.

Il exécute l'algorithme glouton puis OR-opt depuis chaque ville de départ possible.

Ensuite, il conserve uniquement la meilleure solution obtenue.

Gestion mémoire

Le projet utilise de la mémoire dynamique avec les tableaux alloués par new[].

Nous avons donc créé des fonctions permettant :

  • D'allouer la mémoire
  • D'initialiser les structures
  • De libérer correctement la mémoire

Cela évite les fuites mémoire et permet de gérer des instances de tailles différentes.
